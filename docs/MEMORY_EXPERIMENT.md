# 外置记忆离线对照实验

## 目的与边界

本实验只比较记忆检索和上下文构造，不向模型发送提示，也不调用网络。它不测 Gemma 的回答准确性、人格表现、中文自然度、文学质量或用户体验。确定性合成对话让所有方法接收相同问题，且包含早期偏好、纠正、承诺、角色秘密、观点归属、作者计划、资源状态、关系和一个没有记录答案的问题。

`D_structured_production_retrieval` 调用当前 `phoneagent_core.memory.retrieve()` 与 `memory.context()`。为了隔离“检索/上下文”而不混淆“自动记忆抽取”，D 的合成事实由脚本用 `memory.add(..., human=True)` 加入，并人工设定实体、受众、槽位、来源和认知状态。这相当于已正确标注的检索夹具，不表示自动抽取能生成这些标签。结果同时运行 `memory.candidates()` 的规则抽取探针，单列其漏项。

B 是逐轮更新的确定性抽取式滚动摘要替身：只读取原始用户消息，以明确的偏好、事实/个人资料、纠正、承诺、关系、观点、计划、状态/资源、秘密和事件线索选择原句摘录；按有界预算保留摘录，预算不足时从最旧项开始丢弃，摘要文本显示省略数量及类别，逐题 JSON 保留类别计数。它不读取金标准夹具或预期标签，不调用模型，不做语义改写、同义归并或事实核验。互相矛盾的摘录不会被覆盖；若预算驱逐其中一条，会显式增加省略计数，但不会保留已丢弃内容本身。词面线索也会漏掉没有命中词表的表达，或命中同一消息中的干扰词。C 用生产词法 tokenizer 和 token 估算器在用户原始消息上做词面检索，但不使用实体、受众、有效性、来源或认知状态过滤。A 只给最近完整对话轮次。常规题所有组用同一上下文估算预算 2,400、检索预算 600；另有同义提问和上下文 512 / 检索 40 的低预算压力题。预算是 `quota.estimate_tokens` 的 UTF-8 字节估算，不是真实 tokenizer 的实测值。

## 运行与可复现性

在仓库根目录运行：

```powershell
python scripts/evaluate_memory.py
python -m unittest discover -s tests -p test_memory_experiment.py
```

默认随机种子为 `20261011`，固定数据规模为 100 轮和 200 轮。命令会在 `work/upgrade-20261011/` 写入 `memory-experiment.json`、`blind-eval.jsonl` 和 `synthetic-dialogue.jsonl`。其中 `memory-experiment-revised-before-summary.json` 保存本次改进 B 前、使用相同自然问题和实体过滤的结果；`memory-experiment-initial.json` 另存更早的查询和过滤基线。结果 JSON 记录种子、预算、方法注记、各规模各方法逐题数据、盲评臂映射和抽取探针。SQLite 临时数据库会使用 `sqlite3.Row`，先创建宿主程序要求的 `conversations` / `messages` 基表，再调用 `storage.migrate()`；实验结束删除数据库。

各指标含义：

- `evidence_coverage`：有标准答案证据的问题中，检索到预期记忆/原始消息的比例；无答案题记为 `null`，避免把“空”误算成失败或成功。
- `leak_count`：选中了本题标为禁止的秘密或其他角色观点证据的数量。它是上下文泄露代理指标，不是模型实际披露率。
- `unrelated_evidence_count`：逐题汇总的非预期、非指定禁止项记忆数；用于发现词面匹配过宽，不能直接当作答案错误数。
- `conflict_count`：旧花生过敏陈述和更正后的芝麻过敏陈述同时进入结果的次数。
- `token_estimate` / `within_budget`：生产 UTF-8 字节估算和固定预算检查。
- `context_build_ok` / `context_build_error`：生产上下文构造是否成功；构造异常不视为零 token，也不塞一个伪造的成功上下文。
- `retrieval_latency_ms`：本机 Python 检索/上下文构造的墙钟时间；受机器负载影响，不代表上游或端到端延迟。

“作者已写完吗”题只检查计划记录是否被召回。离线脚本没有模型回答，因此不能根据检索分数断言模型会正确地说“尚未发生”。未知题也只衡量系统是否召回了无关证据；不能衡量模型是否会编造答案。

逐题 D 指标以真实 `context()` 返回的 `memory_ids` 计分；同一行另记带实体参数的直接 `retrieve()` 结果和 `context_entity_filter`，供定位差异。旧基线输出保存在 `memory-experiment-initial.json`：在实体过滤集成前的旧问题里，D 对显式询问 Mira/Noah 观点的上下文出现两次观点串角。当前 `context()` 会在查询唯一明确提到一个已知实体（排除通用 `user` / `author`）时传入实体过滤；显式点名的观点题会记录实体过滤后的结果。另有“不同人的看法分别是什么”题检验不应强行过滤：无唯一实体时应保留跨实体信息。该启发式可能漏掉语义上指向他人但没点名的提问，也可能在跨实体问题未被识别为多方时造成遗漏，因此不能外推为完整的观点隔离方案。

查询已移除直接答案词。同义提问“饮品口味如何？”不复用记忆中的“茶/咖啡”等词，专门暴露词面检索对同义表达的失败。低预算压力题设上下文预算 512、检索预算 40；当前上下文构造器有 system/scaffold 占预算一半的约束，因此该题可能在形成提示前失败。发生失败时 JSON 记录 `context_build_ok=false`、异常和 `unavailable_arms`，盲评素材不会伪造 D 的提示；评审应把它记为上下文构造失败且跳过模型提交。另有跨实体问题确认实体启发式在查询确实要求不同人物时不强行过滤。请逐题查看结果，不把总覆盖率当成通用能力证明。`memory-experiment-initial.json` 是实体过滤集成前、旧查询下的原始输出快照；当前 `memory-experiment.json` 对应修改后的自然问题、实体过滤和新增压力题。

本次输出中，D 在 100 / 200 轮数据的支持题平均覆盖率均为 0.8462；“饮品口味如何？”两档都没有召回目标记录，512-token 上下文题两档都在 prompt 构造阶段失败。点名角色的观点题没有观察到禁止观点泄露；跨实体问题保留了 Mira 和 Noah 两条观点，但同时带入 5 条非目标记忆。B 的新抽取式摘要支持题平均覆盖率为 0.9231（改进前快照为 0.1538），但在每种规模的评测查询中累计出现 8 条禁止证据和 14 次新旧过敏陈述同时出现；不能把召回增加说成整体质量改善。512-token B 摘要压力题省略 10 条摘录，日志保留被省略类别。更早的 12 题基线中 D 各有 2 条泄露；查询不同，所以这不是实体过滤单项的因果比较。金标准人工夹具下的覆盖也不包括自动抽取质量；探针仍只捕获 11 条目标事实里的 3 条。

## 人工盲评协议（未来真实模型对照）

`blind-eval.jsonl` 每行是一道题，含查询和四个匿名 `arm_1` 至 `arm_4` 上下文。数据不含组名、标准证据标签或预期答案。组名映射只在 `memory-experiment.json` 的 `blind_arm_key`；正式盲评时由不参与打分的协调者保管此文件，并在锁定评分后揭盲。每题的匿名映射独立随机，避免评审通过某个固定臂编号猜方法。`synthetic-dialogue.jsonl` 提供对应的合成原始对话，供核对事实来源；其中只含合成姓名和内容。

建议步骤：

1. 对同一题的四个匿名臂使用同一固定模型版本、同一系统提示、同一采样参数回答同一问题；每个可用上下文只生成一次，先随机化提交顺序。若 `unavailable_arms` 列出了某个臂，该条件没有生成提示，评为上下文构造失败并跳过模型提交。若需估计生成随机性，可预先规定相同的多组种子并对所有可用臂逐一重复。
2. 评审只看题目、四个匿名回答及必要时的合成对话来源，不看臂映射或本报告的逐臂分数。不得把本离线覆盖分数伪装成模型回答结果。
3. 每题独立记录：事实正确性（0–2）、是否引用了错误/过时事实（是/否）、是否泄露不该给当前角色看的信息（是/否）、是否把计划说成已完成（是/否）、未知问题是否坦白（是/否）、是否正确区分用户和角色观点（是/否）。可另记自然度 1–5，但应作为主观次要指标，不能替代事实和隐私指标。
4. 至少两位评审独立评分；保留原始匿名评分和分歧，报告逐题差异、均值/比例及样本数。对泄露和计划/事实混淆分别报告，不将其折叠为一个总分。评分和分析方案在揭盲前固定。
5. 锁定评分后由协调者读取 `blind_arm_key` 揭盲。最终报告需注明模型/版本、提示、参数、重复次数、日期和是否联网，并将未来真实模型结果与当前离线检索指标分开呈现。

## 限制

测试语料规模小且刻意包含可词面匹配的表达，不能代表开放域中文对话。D 使用金标准元数据，会高估生产端到端表现；候选探针显示当前规则抽取覆盖的真实范围。当前 `context()` 根据查询中唯一明确命中的已知实体名推导 `entity_filter`，而直接 `retrieve()` 的对照由实验显式提供实体参数；多实体或隐含指代不保证被过滤。两条指标按各自实际 `memory_ids` 分开评估。词数预算不是模型 tokenizer 预算。结果适用于发现明确的检索、隔离和预算失败，不适用于声称整体记忆“更聪明”或回答“更有文学性”。
